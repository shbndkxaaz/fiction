# 04 · 使用手册（续写工坊 / Fiction Weaver）

> 面向使用者。想改代码看 `docs/03-merged-architecture.md`；想知道为什么报 `manifest.json is missing` 看 `README.md` 的「安装」。
> 手册对应当前版本 **v0.2.0**（界面 = 全屏工作台，8 个测试文件 / 306 条断言全绿）。

---

## 0. 一句话说清它是什么

> **把你上传的那本小说 TXT，变成 AI 的「长期记忆」，然后两种方式用：**
> ① 在酒馆聊天里「穿书/角色扮演」时，AI 自动知道前情（不剧透后面）；
> ② 在同一个窗口里让 AI 帮你续写、润色，用的还是同一份记忆。

和你之前用的两个项目比，最大的不同是 **一份知识库、两条生产线共用**：
演的和写的永远是同一本书，不会出现「聊天里演到第三章、续写却从第一章开头」的割裂。

```
        TXT ──分段──▶ 逐段清洗（你填的 API）──▶ 剧情节点 / 角色 / 世界设定 / 伏笔
                                                        │
                                        ┌───────────────┴────────────────┐
                                        ▼                                ▼
                          聊天注入（并进第一条 system）        工作台里的 AI 续写 / 润色
                          演到哪只喂到哪（不剧透）              同一份设定 + 已有正文
```

## 1. 合并了什么？两个上游各贡献了哪一半

你上传的两个项目是 **xu-xie-ji**（偏写作工作台）和 **novel-injector-2w**（偏原著注入）。
它们是「单入口巨型 index.js」（8.5k / 8k 行），**没有拼代码**，而是把纯逻辑抽出来重写成 `lib/` 纯函数 + 一个薄装配层。
下面这张表就是「你现在拿到的功能来自谁」：

| 功能 | 来源 | 实际状态 |
|---|---|---|
| TXT 导入 → 按体积分段（**不切半句话**）、自动识别章节 | novel-injector（`splitTextBySize` / `findSafeChapterCutPosition`） | ✅ 可用 |
| 逐段清洗：原文 → `compressed` + 剧情节点 + 角色 + 世界设定（严格 JSON） | novel-injector 的清洗 schema | ✅ 可用 |
| 清洗**断点续跑**：失败的分段单独记错误，下次只补跑没完成的 | 本项目新增 | ✅ 可用 |
| Token 预算裁剪 + 句界截断 + 「本轮丢了什么」记录 | novel-injector `niBuildBoundedStageInjection`（32000 token / 1 字≈0.667 token） | ✅ 可用 |
| 注入**并进第一条 system**（不塞独立 system 消息） | novel-injector 踩坑经验（Claude / Gemini 会丢额外 system） | ✅ 可用 |
| 阶段（stage）过滤：只注入当前阶段之前的节点 | novel-injector | ✅ 可用 |
| 角色退场（`exitStage`）后不再注入 | novel-injector 的 canon 思路 | ✅ 可用（清洗时模型给值） |
| 世界设定**关键词触发**（有词才注入，没词常驻） | xu-xie-ji | ✅ 可用 |
| 「下一个剧情节点」当预告（防写偏，算剧透，默认关） | novel-injector 的 future injection | ✅ 可用 |
| 分层总结（小总结→大总结）注入块，保留最近 3 条 | xu-xie-ji `buildSummaryBlockFromState` | 🟡 注入可用；**自动生成/自动合并还没接进 UI** |
| 长期伏笔一张表（未回收的才注入） | xu-xie-ji + novel-injector 的 `【伏笔】`标记 | 🟡 清洗自动登记可用；手改状态还没做 UI |
| 续写工作台：多分支、定向要求、目标字数 | xu-xie-ji | ✅ 可用 |
| 去 AI 味润色（只润本轮新增） | xu-xie-ji | ✅ 可用 |
| 草稿自动保存（跟书走，不跟聊天走） | xu-xie-ji | ✅ 可用 |
| 书维度存储（一本书跨多个对话） | xu-xie-ji | ✅ 可用 |
| 进度指针存 `chat_metadata`（换对话各自独立） | novel-injector | ✅ 可用 |
| 注入预览（本轮塞了什么、多少 token） | novel-injector 的「运行记录/预览」 | ✅ 可用 |
| 数据体检 / 运行日志面板 | novel-injector | ⬜ 未做 |
| 向量召回（embedding 检索） | novel-injector `vector-system` | ⬜ 未做（M5） |
| **全屏工作台 UI**（左侧分页，不再往抽屉里堆） | 本项目新增 | ✅ 本次新增 |

**一句话总结**：novel-injector 给了「原著怎么进库、每轮塞多少」，xu-xie-ji 给了「怎么续写、怎么记住总结和伏笔」，
新项目做的是把它们粘在**同一个数据模型**上，并重写了两个上游都没解决好的界面。

### 明确没合并的（避免误解）

- 两个上游的 `template.html` / `style.css` 全部丢弃（体量太大、风格冲突），界面重写。
- novel-injector 的向量检索、知识矩阵、健康检查：**代码没搬**，等后面里程碑。
- xu-xie-ji 的「自动分章 / 原创归档 / 角色卡生成」：没搬（README 里标了 v1 砍掉）。

## 2. 界面在哪（这是本次最大的改动）

以前（你截图里的样子）所有东西都堆在酒馆「扩展设置」抽屉里，手机上挤成一长条、要滚很久、还容易点错。
现在是**两层界面**：

### 2.1 抽屉里只留一张「入口卡片」

位置：酒馆顶栏 **扩展设置（插头图标）→ 续写工坊 Fiction Weaver**

```
┌─────────────────────────────────────────────┐
│ 续写工坊 Fiction Weaver      [ 打开工作台 ] │
│ 《断桥记》 12.4 万字 · 节点 86 · 已清洗 3/3 段 │
│ 进度：第 1 阶段 / 节点 12（注入已关闭）      │
└─────────────────────────────────────────────┘
```

- 只有 **一个按钮 + 两行状态**，不占地。
- 状态行永远告诉你：哪本书、多少字、抽了多少节点、清洗进度、演到哪、注入是否开着。

### 2.2 点「打开工作台」→ 全屏工作台

```
┌───────────────────────────────────────────────────────────────┐
│ 续写工坊 · 工作台   《断桥记》· 第1阶段/节点12  ☑启用注入 [关闭]│
├──────────┬────────────────────────────────────────────────────┤
│ ① 书库   │                                                    │
│ ② 清洗   │        当前分页的内容（一次只看一件事）            │
│ ③ 注入   │                                                    │
│ ④ 进度   │                                                    │
│ ⑤ 续写   │                                                    │
│ ⑥ 说明   │                                                    │
├──────────┴────────────────────────────────────────────────────┤
│ 底栏状态：《断桥记》12.4万字/120章/3段(已清洗3) · 节点86 · …  │
└───────────────────────────────────────────────────────────────┘
```

- 电脑上是一个居中大窗口（最大 1080×800），**手机上自动铺满整屏**，左侧导航变成顶部横向标签条。
- 关闭方式三种：右上角「关闭」按钮、点窗口外的灰色遮罩、按 **Esc**。
- 关掉工作台不会影响注入：注入是后台钩子，跟窗口开不开无关。

| 分页 | 干什么 | 什么时候用 |
|---|---|---|
| ① 书库 | 新建/切换/删除书、导入 TXT、导入导出 JSON | 第一次用、换书、备份 |
| ② 清洗 | 填清洗 API、跑清洗 | 刚导入 TXT 之后（唯一花钱的大头） |
| ③ 注入 | 注入位置/深度/预算、预告开关、预览 | 想让 AI 别忘前情、想调省 token |
| ④ 进度 | 阶段/节点指针、推进 | 每演完一段原著 |
| ⑤ 续写 | AI 续写、多分支、润色、草稿 | 想自己往下写 |
| ⑥ 说明 | 内置四步教程 | 忘了怎么用 |

## 3. 十分钟跑通（照抄就行）

> 前提：酒馆能正常聊天（模型已经配好）。

### 第 1 步 打开工作台
顶栏插头图标 → 找到「续写工坊 Fiction Weaver」→ 点 **打开工作台**。

### 第 2 步（① 书库）导入原著
1. 「导入原著 TXT」→ 选你的 `.txt`。
2. **不用先新建书**：没书时会自动用文件名建一本。想自己起名就先填书名 → 新建。
3. 分段大小先保持 **60000**（6 万字/段）。等跑过一次再考虑调。
4. 底栏应该立刻变成 `《你的书名》 xx万字 / N 章 / 1 段（已清洗 0）`。

预期看到 `② 清洗` 之外的提示：`② 清洗` 那页的提示行会写「已导入 N 章 / M 段，可以去清洗了」。

### 第 3 步（② 清洗）填 API
填三样，缺一不可：

| 字段 | 例子 | 注意 |
|---|---|---|
| 地址 | `https://api.openai.com/v1/chat/completions` | OpenAI 兼容端点；只填到 `/v1` 会自动补 `/chat/completions` |
| Key | `sk-...` | 只存在浏览器的 localStorage，不进仓库、不上传别处 |
| 模型 | `gpt-4o-mini` / `deepseek-chat` / `qwen-plus` | 要**能吃长输入**的模型（一段 6 万字 ≈ 4 万 token） |

### 第 4 步（② 清洗）开始清洗
点 **开始清洗（未完成的段）**，然后看提示行逐段跳：

```
清洗第 1 / 3 段（60000 字）…
第 1 段完成：+8 节点 / +6 角色 / +4 设定
…
清洗结束：完成 3 段，失败 0 段。
```

- 想停就点 **停止**（当前这段会跑完才停，不会白花钱）。
- 失败会显示原因（如 `HTTP 401`），**再点一次开始清洗只补跑失败的段**。
- 跑完底栏的 `节点 N / 角色 N / 世界设定 N` 会变成真实数字。

### 第 5 步（③ 注入）先预览，别急着聊
点 **预览本轮注入**，会看到类似：

```
字数 12800 / 约 8534 token（预算 32000）

— stage（4200 字）
【当前阶段剧情（第1阶段）】
1. 断桥夜会
林昭在断桥等沈砚…

— chars（3100 字）
【角色人设】
姓名：林昭（别名：昭儿）
…
```

- 第一行：**总字数 / 估算 token / 本轮预算**。
- 任何块被预算挤掉时会多一行 `因预算省略：style`（说明哪些没塞进去）。
- 下面是每一块的 key 与正文（key 的顺序就是占预算的优先级，见第 5 节）。

看到的东西就是「AI 这一轮会知道什么」。**如果这里是空的**：不是坏了，说明当前阶段没有节点（检查 ④ 进度）或书没清洗。

### 第 6 步（④ 进度）对齐你演到哪
- 「节点序号 -1」= 还没开始（只注入人设/世界设定）。
- 每演完一段原著剧情，点一次 **推进一个节点**（+1）。
- 阶段（stage）目前要你手改：原著大段落切换时把「阶段」+1，注入就只喂到这一阶段为止。

### 第 7 步 回聊天正常聊
不用做任何操作，注入是自动的；底栏/卡片上会显示 `启用注入` 是否勾着。
想临时关掉：取消顶部 **启用注入** 勾选（完全不注入、不发任何请求）。

### 第 8 步（⑤ 续写）让它帮你写
1. 「分支数」先设 1，「目标字数」800。
2. 想让剧情按你的意思走，就在「定向要求」写一句，例：`让沈砚先起疑，但别当场拆穿，末尾留一个钩子`。
3. 点 **AI 续写** → 生成结果出现在「生成结果」区。
4. 满意就点 **追加到草稿**；想直接用就点 **填入输入框**（填进酒馆输入框，**你自己按发送**，插件不改聊天记录）。
5. 草稿有 AI 味？点 **润色草稿（去 AI 味）**，它会整段重写草稿（保留剧情、改文风）。
6. 草稿自动保存到书里，关掉工作台也不会丢。

## 4. 每个控件逐条说明

### ① 书库

| 控件 | 默认 | 作用 / 注意 |
|---|---|---|
| 当前书（下拉） | 上次用的那本 | 切换书会立刻换掉整份知识库；注入、续写都跟着变 |
| 删除这本书 | — | 会二次确认；**清洗结果、总结、伏笔、草稿一起没**，不可撤销 |
| 书名 + 新建 | 空 | 留空也行（导入 TXT 时自动用文件名）。一本书 = 一份知识库 |
| 导入原著 TXT | — | 追加式：同一本书可以分几次导入不同文件（第二次导入会新增分段） |
| 分段大小（字） | 60000 | 每段喂给清洗模型的体积。**小 = 抽得细 = 花钱多**；`2000~200000` |
| 导出全部（JSON） | — | 备份整库（含所有书、设定、进度、草稿）。换机器/清缓存前必做 |
| 导入 JSON | — | 按书的 id 覆盖写入，返回导入了几本 |

### ② 清洗

| 控件 | 默认 | 作用 / 注意 |
|---|---|---|
| API 地址 | 空 | OpenAI 兼容端点。填 `.../v1` 会自动补成 `.../v1/chat/completions` |
| API Key | 空 | password 框；存在 localStorage（只在你本机）。公开演示时记得清空 |
| 模型名 | 空 | 清洗/润色都用它。要能一次吃 6 万字输入（约 4 万 token） |
| 开始清洗（未完成的段） | — | 只跑 `done=false` 的段；失败段会自动重试，不会重复花钱 |
| 停止 | — | 当前段跑完才停（不会留下半截脏数据） |
| 提示行 | — | 每段一行：`+节点/+角色/+设定`；失败显示具体原因 |

清洗会产出四样东西（都进书里，底栏能数）：
`compressed`（压缩正文，给注入兜底）、`nodes`（剧情节点）、`chars`（角色）、`world`（世界设定）。
节点里带 `【伏笔】` 的会自动进伏笔表（状态 `planned`）。

### ③ 注入

| 控件 | 默认 | 作用 / 注意 |
|---|---|---|
| 注入位置 | 并进主提示 | **推荐**。并进第一条 system 的文本，兼容性最好（Claude/Gemini 不会丢） |
| ↳ 聊天内（另一选项） | — | 插一条独立 system 消息，位置由「深度」决定；部分中转会把它当主提示词替换，慎用 |
| 深度 | 4 | 只对「聊天内」生效：0 = 贴着最新一条消息，数字越大越靠前 |
| 单轮预算（token） | 32000 | 本轮注入的上限。超出按优先级丢内容（见第 5 节） |
| 注入下一个节点当预告 | 关 | 开了 AI 能看到「下一章要发生什么」，写得更顺但**算剧透** |
| 预览本轮注入 | — | 不发请求，只算这一轮塞什么、多少 token、丢了什么 |

### ④ 进度

| 控件 | 默认 | 作用 / 注意 |
|---|---|---|
| 阶段 | 1 | 注入只要 `stageIdx = 当前阶段` 的节点。换大段落时手改 +1 |
| 节点序号 | -1 | `-1` = 还没开始。注入按它判断「下一个节点」是谁 |
| 推进一个节点 | — | 就是把节点序号 +1，并写进进度（聊天记录不动） |

进度的存法（重要的设计）：**指针存在对话（`chat_metadata.fw.progress`），书里只存一份兜底**。
所以「同一本书 + 两个对话」可以各自演到不同位置，互不影响。

### ⑤ 续写

| 控件 | 默认 | 作用 / 注意 |
|---|---|---|
| 分支数 | 1 | 1~3。>1 时提示词里会要求用 `===分支===` 分开，回来就是 N 张卡片 |
| 目标字数 | 800 | 100~4000。太少容易断在半句，太多模型会灌水 |
| 定向要求 | 空 | 一句话方向，例：`让男主发现线索但别揭晓`。**填了就会作为「本次续写要求」进提示词** |
| AI 续写 | — | 用**酒馆当前模型**（不是②的清洗 API）。上下文 = 知识库注入块 + 已经写到的末尾 |
| 润色草稿 | — | 用②的清洗 API；只改文风、改 AI 味，不动剧情事实 |
| 清空草稿 | — | 清掉这本书的草稿（有确认感，先落盘再清） |
| 生成结果 | — | 每个分支一张卡：**追加到草稿** / **填入输入框** |
| 草稿 | 空 | 输入后 0.8 秒自动存进书；关工作台也会存一次 |

续写的上下文从哪来：草稿非空 → 用草稿的末尾 4000 字；草稿空 → 用聊天里**最后一条 AI 消息**的末尾。

## 5. 注入到底算了些什么（看懂这一节就不会「AI 失忆」）

### 5.1 七种块 + 固定优先级

| 优先级 | key | 内容 | 丢的先后 |
|---|---|---|---|
| 0 | `stage` | 当前阶段所有节点明细（标题 + 发生了什么） | 最后一个丢 |
| 1 | `chars` | 角色人设（姓名/别名/身份/外貌/性格/关系） | ↓ |
| 2 | `world` | 世界设定（有关键词且命中当前上下文才注入） | ↓ |
| 3 | `summary` | 分层总结（保留最近 3 条） | ↓ |
| 4 | `foreshadow` | 还没回收的伏笔 | ↓ |
| 5 | `future` | 下一个剧情节点（默认关） | ↓ |
| 6 | `style` | 文风指南 | 最先丢 |

装配规则（对齐 novel-injector）：按优先级依次占预算 → 装不下就在**句子边界**截断并标记 → 之后不再追加更低优先级的块，
被完全挤掉的块记进 `omitted`，预览里会写「因预算省略：xxx」。

估算比固定 **1 字 ≈ 0.667 token**（`CHARS_PER_TOKEN = 1.5`），所以 1000 字 ≈ 667 token；预算 32000 token ≈ 48000 字。

### 5.2 防剧透的三个阀门

1. **阶段过滤**：只注入 `stageIdx === 当前阶段` 的节点，后面阶段的一律不给。
2. **节点指针**：`future` 块最多只给「下一个节点」，且默认关闭。
3. **角色退场**：`exitStage > 0 && 当前阶段 >= exitStage` 的角色不再注入（避免「已写死的人还在说话」）。

### 5.3 为什么并进第一条 system，而不是新加一条

novel-injector 踩过的坑：Claude / Gemini 适配器会合并或丢弃额外的 system 消息，部分中转还会把 `messages[0]` 当主提示词整体替换。

## 6. 三种典型玩法（推荐工作流）

### 玩法 A：穿书（聊天演戏，最常用）

1. 导入 + 清洗一次（脏活只有这一次）。
2. ④ 进度定在你要演的位置（想从第一章重演就 `阶段 1 / 节点 -1`）。
3. 聊天里正常推进；**每演完一段原著点一次「推进一个节点」**。
4. 觉得 AI 开始失忆 → ③ 点「预览本轮注入」看是不是被预算挤掉了（`因预算省略：…`）。
   常见修法：把预算从 32000 调到 48000，或把「分段大小」调小重洗一遍（节点更细）。

### 玩法 B：接着原著往下写（写小说）

1. ④ 进度推到原著**最后一节**（别让它继续按原著演）。
2. ③ 的「注入下一个节点当预告」保持**关闭**（后面已经没有原著节点可预告了），方向交给 ⑤ 的「定向要求」。
3. ⑤ 分支数设 2~3，定向要求写一句方向 → 挑一个满意的「追加到草稿」。
4. 草稿攒够一段 → 「润色草稿」→ 「填入输入框」→ 自己发送（这样正文就进了聊天记录，成为下一轮的上下文）。
5. 攒到 6000~10000 字后，建议**重新导入这段新正文并清洗**，让知识库跟上你写的内容
   （自动回流是里程碑 M4，还没做，目前这一步要手动）。

### 玩法 C：只用注入，不续写

只要你想要「AI 记得这本书」，② 之外什么都不用点。
⑤ 不点就不会花续写的钱；① 里随时可以换书。

## 7. 数据存在哪 / 怎么备份

| 数据 | 存在哪 | 会不会丢 |
|---|---|---|
| 书（分段/节点/角色/世界/伏笔/草稿） | 浏览器 `localStorage`，键 `fiction_weaver_story_<id>` | **清浏览器缓存 / 换设备 / App 重装会丢** |
| 书列表、当前书 | `localStorage`：`fiction_weaver_story_list`、`fiction_weaver_active_story` | 同上 |
| 插件设置（API、预算、分支数…） | 酒馆的扩展设置文件（`extension_settings['fiction-weaver']`） | 跟酒馆设置一起走 |
| 进度指针 | 当前对话的 `chat_metadata.fw.progress` | 跟对话走，删对话就没 |

**备份 = ① 书库 → 导出全部（JSON）**。建议每次清洗完、写完一章各导一次。

⚠️ localStorage 有容量上限（一般 5MB 左右）。一本 30 万字的书大概占 1MB 上下；导入多本超大体积的书可能写不进去，
控制台会打印 `[续写工坊] localStorage 写入失败（可能超额或隐私模式）`。遇到就把不用的书导出后删掉。

## 8. 常见问题（按你实际会遇到的顺序）

**Q1. 装的时候提示 `Extension manifest.json is missing`**
`git clone` 下来的仓库根目录没有 `manifest.json`（或扩展被放在了子目录）。见 `README.md` 的「安装」四条路：
自带脚本（`node tools/install.mjs <SillyTavern目录>`）/ 手动复制 / `--zip` 传手机 / 先推到 GitHub 用 URL 装。
**用 URL 装的话，扩展必须在仓库根目录，一个仓库只放一个扩展。**

**Q2. 扩展列表里找不到，或者抽屉里没有卡片**
- 「管理扩展」里看是不是被禁用了（开关打开后刷新页面）。
- 打开浏览器控制台看有没有 `[续写工坊] 初始化失败`：多半是 `template.html` 没跟着拷过去（`index.js` 是自己 fetch 模板的）。
- TauriTavern / 手机端：装完要**重启 App**，只刷新不行。

**Q3. 点「开始清洗」提示「先填清洗 API 地址和模型」**
② 里的地址和模型名都要填（Key 可空，某些本地端点不要 Key）。

**Q4. 清洗失败：`HTTP 401 / 403`**
Key 错、Key 没额度、或中转要求额外 header。401 一律先怀疑 Key。

**Q5. 清洗失败：`模型返回里没有剧情节点，也没有压缩正文`**
模型没按 JSON 输出（小模型常见）。换大一点的模型，或换兼容 OpenAI `response_format` 的服务；重跑只会补跑这一段。

**Q6. 清洗提示「所有分段都清洗过了」**
想重洗就删掉这本书重新导入（目前没有「单段重洗」按钮）。

**Q7. 聊了半天，AI 还是不知道前情**
按顺序排查：① 顶部「启用注入」是否勾着 → ② 是否选了书 → ③ ③ 页「预览本轮注入」有没有内容
→ ④ 若预览为空：④ 进度阶段是不是没有对应节点（清洗时模型给的 `stageIdx` 都是当前阶段）
→ ⑤ 用的模型是不是走酒馆的 Chat Completion（走 Text Completion 或某些外部直连不会触发 `CHAT_COMPLETION_PROMPT_READY`）。
控制台里若出现 `[续写工坊] 当前酒馆版本没有 CHAT_COMPLETION_PROMPT_READY`，说明酒馆版本太老。

**Q8. AI 老剧透后面的剧情**
③ 里「注入下一个节点当预告」关掉；④ 的阶段别超前；检查预览里有没有 `future` 块。

**Q9. token / 费用突然变高**
看预览第一行的 token 数。三个大户：`stage`（节点明细）、`chars`（角色太多）、`world`（没写 keywords 的条目会**常驻**）。
把预算降到 16000 试试，或把世界设定条目补上关键词让它按需触发。

**Q10. 点「AI 续写」提示「当前酒馆版本没有 generateRaw，无法续写」**
酒馆版本太老。升级酒馆，或只用注入功能。

**Q11. 点「填入输入框」提示「找不到聊天输入框，请手动复制」**
你的酒馆 UI 改了 `#send_textarea` 的 id（换主题/装别的扩展改的）。手动复制草稿即可。

**Q12. 草稿/书突然没了**
99% 是清了浏览器缓存或换了设备/浏览器。以后记得定期「导出全部」。
隐私模式（无痕）下 localStorage 可能不落盘，别在无痕窗口里做清洗。

**Q13. 我改了正文，但知识库还是老的**
这是当前版本的已知限制：**写出来的新正文不会自动回流成节点/总结**（M4 未做）。
手动办法：把新写的正文存成 TXT，① 里再导入一次（会作为新分段追加），然后 ② 清洗（只会跑新段）。

**Q14. 手机上界面还是挤**
确认装的是 v0.2.0 及以后：抽屉里应该只剩一张卡片（一个「打开工作台」按钮）。
旧版本是 6 个区块直接铺在抽屉里的。升级后**重启 App** 再看。

## 9. 花费估算（举例，按供应商现价自己算）

中篇 30 万字，分段 60000 → **5 段**：

| 项目 | 量级 | 说明 |
|---|---|---|
| 清洗输入 | ≈ 20 万 token | 30 万字 ÷ 1.5 |
| 清洗输出 | ≈ 1.5~3 万 token | 每段 3~6k（JSON 节点） |
| 润色 | 每 800 字 ≈ 550 token 输入 + 输出 | 只在 ⑤ 点的时候花 |
| 聊天注入 | **不额外花钱** | 注入是把你自己的 token 预算用在提示词里，按你聊天模型的输入价算 |

以「每百万 token 输入 ≈ 1 元、输出 ≈ 4 元」的便宜模型算，30 万字小说「洗一次」大约 **几毛到一两块钱**。
贵模型会贵 10~50 倍。**省钱三招**：分段调大、只清洗你要用的阶段、别反复删书重洗。

## 10. 当前限制与下一步（老实说）

- ⬜ **无 LICENSE**：两个上游都没给许可证，公开发布前必须解决（详见 `docs/03-merged-architecture.md` 第 8 节）。

- ⬜ 没有「单段重洗」和「运行日志面板」。

## 11. 附：文件与命令速查

| 命令 | 作用 |
|---|---|
| `node tools/install.mjs <SillyTavern目录>` | 装到该酒馆（自动选 `data/<用户>/extensions/third-party/fiction-weaver`） |
| `node tools/install.mjs <目录> --global` | 装到 `public/scripts/extensions/third-party/`（所有用户可见） |

运行时文件只需 5 样：`manifest.json`、`index.js`、`style.css`、`template.html`、`lib/`。
（`docs/`、`tests/`、`tools/` 不进安装包。）
