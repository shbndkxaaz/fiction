## 3. 功能模块逐个看

### 3.1 存储层：`storyId` 作用域 + 迁移
`getStoryScopedKey(baseKey, storyId)` → `${baseKey}::${storyId}`；`getStrictStoryScopedKey` 用更严格的序列化。
`migrateLibraryToStrictKeyOnce` / `migrateStateToStrictKeyOnce` / `migrateLegacyScopedStorage` 负责老版本 key 升级。
`switchStory(storyId)`、`clearStoryScopedRuntimeState()` 保证「切故事 = 切全部数据」，不串档。

> **结论：数据是 localStorage 里的「书（story）」维度**，不是聊天（chat）维度。这一点和 novel-injector 正好相反。

### 3.2 分层总结（过去）
- `loadAutoSummaryState / saveAutoSummaryState / resetAutoSummaryState`：状态 = `{ summaries: 小总结[], majorSummaries: 大总结[] }`，每条带 `start/end`（对应正文字符偏移）。
- `summarizeTextWithTarget` / `summarizeChunksToText`：调总结 API（或 `generateRaw`）。
- `maybeMergeAutoSummaries(state)`：小总结攒够 `autoSummaryMergeCount`（默认 8）→ 合并成「长期大总结」；`autoSummaryKeepRecentCount`（默认 3）保留原文粒度。
- **v92 的关键设计**：打包进大总结的小总结会从状态和总结库中删除，避免摘要无限堆积。
- `buildSummaryBlockFromState(state)` 产出注入文本：

```
【长期大总结】
【大总结1｜原文0-12345字】……
【最近小总结】
【最近摘要1｜原文12345-15000字】……
```

- `getLastOriginalSummarizedEnd()` + `runAfterContinuationSavedPipeline()` + `maybeNotifyManualPostprocessNeeded()`：保存正文后判断「未总结字数是否超过阈值（建议 6000~12000）」。

### 3.3 TXT 导入 / 章节 / 自动切章
- `detectTxtChapters(text)`：正则识别「第X章 / 第X节 / 序章 / 番外」，中文数字经 `parseChineseChapterNumber` 归一。
- `splitTextBySize`、`findSafeChapterCutPosition`、`extractContinuationCarryTail`、`buildPostprocessEditorRemainder`：**只在完整句尾切**，绝不半句切断（README 反复强调）。
- `ensureAutoChapterAfterContinuation()`：续写保存后按目标字数（默认 6000）+ 完整句尾自动成章，`appendAutoChapterToImportedState` 归档原文，`analyzeAutoGeneratedChapter` 自动跑世界书分析。

### 3.4 世界书（现在）
- 数据模型（`normalizeWorldBook`）：`{ characters: [], plot: [], world: [] }`，每条 `createWorldBookItem` = `{ id, title, content, enabled, tags, ...extra }`；兼容旧版三大文本框（`characterSetting / plotOutline / worldSetting`）。
- `compileWorldBookToLegacy(worldBook)`：把结构化书编回三大文本块，供旧逻辑使用。
- **按需触发**：`splitWorldBookKeywords(item)`、`isWorldBookItemTriggered(item, contextText, category)`、`buildTriggeredWorldSetting(contextText)` —— 只有当前正文命中条目关键词才注入，这是它控制 token 的主要手段（对比 novel-injector 的向量召回）。
- AI 分析链：`buildWorldBookAnalysisPrompt` → `callWorldBookAnalysisAI`（独立 API）→ `parseWorldBookAnalysisStrict` → 多级降级修复（`repairWorldBookAnalysisLocally`、`salvageWorldBookFromLooseText_ACU`、`tolerantParseWorldBookJson`、`autoPostProcessWorldBookJsonText`）→ `mergeWorldBookItems` 去重合并。
- 断点续跑：`getWorldBookResumeState / saveWorldBookResumeState / refreshWorldbookResumeButton`；`buildWorldBookChunksForAnalysis` 按 `summaryChunkSize` 切片。
- 失败留痕：`pushWorldBookAnalysisLog` + `openWorldBookAnalysisLogModal`。

### 3.5 长期伏笔（未来）
- `getForeshadowStorageKey / loadForeshadowMemory / saveForeshadowMemory / normalizeForeshadowItem`。
- `registerForeshadow(directionText)`：把「定向续写」输入框内容登记为伏笔（UI 上是输入框旁的「伏笔」开关 `#directional_mode_toggle`）。
- `openForeshadowManagerModal()`：按百分比权重（`percent / fromPercent`）管理「后续概率触发」。
- 注入形态：作为 prompt 块 `【长期伏笔】`，与总结、世界书一起进 `buildUnifiedGenerationContext`。


### 3.6 续写核心（生成侧）
调用链：`runMainContinuation()` → `buildGenerateConfig()` → `buildUnifiedGenerationContext(functionType)` → `buildTaskPrompt()`。

- `buildUnifiedGenerationContext` 组装：
  1. `buildSummaryBlockFromState` → 前缀 `【剧情记忆摘要（由总结库临时注入，不属于正文）】`
  2. `【当前未总结正文】`：`ensureRealTextInModelContext()` 保证模型一定看得到真实正文（防「全是摘要没有原文」）
  3. `【世界书】`：`buildTriggeredWorldSetting(...)` 关键词命中项
  4. `【长期伏笔】`
- `buildTaskPrompt({ functionType, ... })`：`continuation | custom(定向) | expand(扩写) | shorten(缩写) | rewrite(改写)`，产出
  `【当前任务】/【文风控制】/【用户定向要求】/【光标前正文】/【光标后正文】/【输出要求】`。
- 生成入口：`generateRawWithBreakLimit(params)`（`getContext().generateRaw`，带破限重试 + 速率限制）、`generateRawWithOptionalStreaming(params, onChunk)`（流式失败自动降级非流式）。
- 参数：`getActivePresetParams()` 取酒馆当前预设；`stop` 词固定追加 `\n\n\n / ### / 原文： / 用户： / 助手： / BRANCH_SEPARATOR` 等。
- 分支：`parseContinuationBranchesFromRaw` → `renderBranchCards()`（多分支卡片预览）；过短分支 `completeShortContinuationBranch` 自动补写；`processStrictContinuationContent` 清洗模型输出（去前言、去标题）。
- 文风：`BUILTIN_STYLE_PROFILES`（12 种内置）+ `customStylesList`；`buildStylePromptForGeneration` 产出 `【文风控制】` 块（强度 weak/medium/strong）。

### 3.7 自动润色（去 AI 味）
`runManualPostprocessCheck` / `maybeNotifyManualPostprocessNeeded` → 调润色 API（`polishApiUrl / polishApiKey / polishModel / polishSystemPrompt / polishUserPrompt`，用户提示词里 `{{TEXT}}` 占位）。
**只润色本轮新增正文**，不动前文、总结、世界书、历史正文（README 明确）。

### 3.8 编辑器 UI
`buildEditorHtml()`（约 220 行模板字符串）+ `bindEditorEvents()`（约 240 行事件）+ `destroyEditor()`。
悬浮全屏编辑器，contenteditable/textarea + 撤销栈（`historyStack`、`maxHistorySteps`）+ 自动保存（`autoSaveInterval`）+ 移动端视口同步（`syncMobileViewportHeight`）+ 导出 `exportContentToFile('txt' | 'md')`。

## 4. 它的强项 / 短板

**强项**
1. 分层总结 + 自动合并，长篇记忆最省 token 的方案之一。
2. 「只在完整句尾切章」「防止半句切断」这类细节打磨得很细。
3. 世界书按关键词触发注入，实现简单、效果稳。
4. TXT 导入 → 总结 → 续写的**写作流**闭环完整，润色、分支、扩写/改写都在。
5. 多故事隔离 + 回收站 + 快照，工程细节扎实。

**短板**
1. **不接入聊天主循环**：不 hook `CHAT_COMPLETION_PROMPT_READY`，只靠 `generateRaw` 自己发请求 —— 所以「在酒馆里和角色演剧情（穿书）」它做不到。
2. 没有原文入库的**向量召回**：长篇前情全靠摘要，细节（某个地名、某句对白）丢了就找不回来。
3. 没有从原著自动抽取 `角色卡 / 剧情节点 / 阶段`，世界书要用户或 AI 现写。
4. 8.5k 行单文件、无测试、无模块边界，任何改造都要动 `index.js`。
